# セキュリティ学習の安全ガイド (必読)

ホワイトハッカーとブラックハッカーの違いは、技術ではなく **許可と倫理** です。
同じ nmap でも、自分の環境に使えば学習ですが、他人のサーバーに使えば犯罪になり得ます。

## 絶対に守ること

1. **攻撃的な操作は、自分が管理する環境か、書面などで明示的に許可された環境にだけ行う**
   - ポートスキャン、脆弱性スキャン、パスワード試行、エクスプロイトの実行など
   - 「公開されているから」「軽く試すだけ」は許可になりません
2. **学習用プラットフォームはスコープとルールを守る**
   - TryHackMe / Hack The Box / CTF は、許可された対象だけを攻撃する
   - バグバウンティは、プログラムごとの対象範囲と禁止事項を必ず読む
3. **職場のネットワークや業務システムで勝手に試さない**。社内でも許可が必要です
4. **見つけた脆弱性や他人の情報を悪用・公開しない**。脆弱性を見つけたら、責任ある開示 (IPA の届出制度など) に従う

## 日本の法律 (概要)

以下は概要です。正確な内容は条文や専門家の解説で確認してください。

| 法律 | 関係する行為の例 |
|---|---|
| 不正アクセス禁止法 | 他人の ID・パスワードを使ったログイン、脆弱性を突いた認証の回避、他人の認証情報の取得・保管 |
| 刑法 (不正指令電磁的記録に関する罪) | 正当な理由のないマルウェアの作成・提供・保管 |
| 刑法 (電子計算機損壊等業務妨害罪) | サーバーを停止させる、データを改ざんする |

## このリポジトリでの安全策

- ラボのネットワークは Docker の中に閉じています
- ホストにポートを公開する場合は **必ず `127.0.0.1` に限定** します (例: `127.0.0.1:8002:80`)
  - `0.0.0.0` で公開すると、同じ Wi-Fi にいる他人からアクセスできてしまいます
- 脆弱なアプリ (Juice Shop, DVWA など) を追加するときは:
  - `internal: true` のネットワークに置き、インターネットに出られないようにする
  - ホストにポートを公開しないか、`127.0.0.1` に限定する
  - 使い終わったら `lab stop` する
- ラボで作った攻撃用スクリプトは、ラボの IP 範囲 (`10.1xx.x.x`) の外に向けない

## AWS を使うときの安全策

- **ルートユーザーに MFA** を設定し、普段は使わない
- **AWS Budgets で予算アラート** を設定する (例: 月 $10 を超えたらメール)
- アクセスキーを **Git に commit しない**。commit してしまったら、すぐにキーを無効化する (履歴から消すだけでは不十分)
- 学習が終わったら `terraform destroy` でリソースを消す。特に NAT Gateway, ALB, RDS は放置すると高額になる
- AWS 上でのペネトレーションテストは、AWS のポリシーで許可されている範囲でのみ行う (公式の「侵入テスト」ページを確認する)
- EC2 のセキュリティグループで SSH (22) を `0.0.0.0/0` に開けない

## 困ったら

- 「これは試してよいのか?」と迷ったら、**やらない**
- 脆弱性を見つけてしまったら、IPA の「脆弱性関連情報の届出」制度を利用できます
