## ヒント1: どこまで届いているか切り分ける

いきなり設定を見る前に、**どこまで届いているか** を確かめましょう。

```sh
# client から
ping -c 2 10.101.1.254   # 自分の隣 (router) には届く?
ping -c 2 10.101.2.254   # router の反対側には届く?
ping -c 2 10.101.2.10    # server には届く?
traceroute -n 10.101.2.10
```

## ヒント2: 各ホストの経路表を見る

`ip route` を client / router / server のそれぞれで実行し、正常時にメモしたものと比べましょう。
client は `10.101.2.0/24` をどこに送ろうとしていますか? server の **返事** はどこに送られますか?

## ヒント3: パケットを覗く

server で `tcpdump -ni any icmp` (nginx コンテナには入っていないので、router で `tcpdump -ni any` するのが手軽) を
実行しながら client から ping してみましょう。

- リクエストは届いているのに返事がない → **戻りの経路** を疑う
- router の片側にしかパケットが見えない → router の **転送** を疑う (`iptables -S`, `ip link`)

## ヒント4: 4 つのシナリオ

障害は次のどれかです。

1. client のルートが消えた
2. server のルートが消えた
3. router のファイアウォールが転送を拒否している
4. router のインターフェースが落ちている

答えは `SOLUTION.md` にあります。まずは自力で!
